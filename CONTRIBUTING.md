# Contributing

Thanks for considering a contribution to Awesome Text-First Interfaces!

## Adding a resource

1. Make sure it's genuinely relevant: a CLI/TUI framework, a text/line-based protocol, or a real example/case study of a text-first interface decision.
2. Add it to the most relevant existing category, or propose a new category if it doesn't fit.
3. One-line description, no marketing language, no fluff.
4. Alphabetical order within a category unless there's a good reason otherwise.
5. Open a PR. Explain briefly why the resource belongs here.

## Reporting a stale or dead link

Open an issue with the link and where it appears in the README, or send a PR removing/fixing it directly.

## Style

- Keep entries factual. If you're citing a benchmark or statistic, link the source.
- Prefer primary sources (the project's own repo/docs) over third-party summaries.
- Keep the "Decision Heuristics" and "When You Actually Need a GUI" sections honest — this list is meant to help people choose correctly, not to advocate blindly for text interfaces.
